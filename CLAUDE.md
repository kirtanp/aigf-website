# AI Governance Forum website

Rebuild of ai-gf.com. **Read `PLAN.md` first**: it has the goals, brand, design quality bar, content model and build steps. Its "Progress" section says what is done and what is next.

## Commands

`justfile` wraps everything (`just` lists recipes); `README.md` has the setup for humans.

```sh
just dev                       # http://localhost:4321 (or npm run dev)
just check                     # astro check (0 errors expected) + build; build validates all content
just shots / /speakers         # desktop + mobile full-page PNGs into screenshots/ (Playwright)
just docker                    # dev server in Docker; `just docker-preview` serves the build on :4322
npm run migrate -- --force     # regenerate content from archive-raw/ (see below)
```

## Layout

- `src/content.config.ts`: Zod schemas for every collection (speakers, editions, pages, and the settings files `current`, `home`, `site`). Content that doesn't match fails the build on purpose.
- `src/content/`: generated by the migration. `speakers/*.md`, `editions/<year>.yaml` (2019–2025 plus a stub `2026.yaml`), `pages/*.md`, `settings/{current,home,site}.yaml`.
- `src/assets/speakers/<slug>.jpg`, `src/assets/logos/<year>.png` (plus `2026-wordmark.png` for the header): generated by the migration.
- `src/lib/data.ts`: all content access and formatting helpers. "Editions spoken at" is computed here from edition files (`getAppearances`), never stored on speakers.
- `src/components/`: Header, Footer, RegisterButton (live link or "Registration link coming soon" from `settings/current.yaml`), SpeakerCard (4:5 photo, greyscale→colour on hover, initials tile fallback), Schedule.
- `src/pages/`: `/`, `/programme` (current edition), `/speakers`, `/speakers/[slug]`, `/editions`, `/editions/[year]` (past editions only), `/[page]` (about, guiding-principles, contact, journal-call), 404.
- `src/styles/global.css`: Tailwind v4 `@theme` brand tokens (dark theme: `paper` is the dark page, `ink` the light text; `brand-indigo` is the true #3C0AFF used by the gradients, `brand-blue` is a lighter tint for accents on the dark page; `.wordmark-white` turns the logo PNG white) and the type scale (`text-display`, `text-title`, `text-lead`; headings use only these), `container-site` (page width and gutters, used by every section), `eyebrow`, `bg-brand-gradient`, `bg-brand-gradient-deep` (ends on #D6006A; use it behind white text), `text-brand-gradient`, `.prose-content`, `[data-reveal]` scroll fade-in (script in `Base.astro`).
- `src/components/`: `PageHeader` (top of every inner page), `SectionHeading` (eyebrow + title + optional "see all" link), `Facts` / `EventFacts` (venue/date/time/format row; `EventFacts` adds the client-side countdown), `Newsletter`, `Schedule`, `SpeakerCard`, `RegisterButton` (`tone="dark"` on the gradient).
- `src/pages/og.png.ts`: default social image, generated at build from the header wordmark. `Base.astro` takes `image`, `jsonLd`, `noindex`; Home and Programme pass `eventJsonLd()` from `data.ts`.
- `.pages.yml`: Pages CMS forms. Must mirror `content.config.ts` field for field. Validate it against Pages CMS's own Zod schema (clone github.com/pages-cms/pages-cms, bundle `lib/config-schema.ts` with esbuild) after changes.
- `public/_redirects` (old WordPress URLs), `public/_headers`, `public/robots.txt`. `.github/workflows/check.yml`: check + build + lychee. `DEPLOY.md`, `EDITING.md`: for humans.
- `Dockerfile` / `docker-compose.yml`: `dev` target mounts `src/` and `public/` for live reload; `preview` target builds and serves.
- `scripts/migrate/`: one-shot migration (`README.md` explains it, `REVIEW.csv` holds human answers).
- `archive-raw/`: 469 MB snapshot of the old WordPress sites (REST JSON, media, wget mirror). Git-ignored; the migration reads from it. Do not edit.

## Rules and gotchas

- **Migration:** re-running with `--force` is fine until editors use the CMS; after that, never, because it wipes `src/content/`. Content fixes before then go in `REVIEW.csv` answers or `editions-meta.mjs`, not by hand-editing `src/content/` (they'd be overwritten).
- Design work is in templates only. Editors fill fields; layouts must cope with long names, missing photos, 2 or 30 speakers and empty programmes.
- White text on the gradient's bright magenta end fails WCAG AA; use `bg-brand-gradient-deep` or large/bold text there. Even on the deep gradient, small text over the magenta end must be pure white (white/65 or /80 fails AA there).
- **CMS quirks:** Pages CMS stores a picked speaker as `jane-doe.md` (its file name), so edition files use that form and the schema's `speakerRef` strips `.md`. Image fields write `../../assets/...` (relative to the content file, as Astro needs) via the media `output`. Schedule links take either an uploaded `file` or a `url`. `settings.content.merge: true` keeps fields the forms don't list (e.g. `logo`, `oldSiteUrl`). Pages CMS drops empty strings and empty lists on save, so any field a form can leave empty must be `.optional()` or have a `.default()` in the schema (and be `required: true` in `.pages.yml` otherwise).
- `astro.config.mjs` casts the Tailwind Vite plugin to `any`: a known type mismatch, not a bug.
- npm blocks install scripts by default here; `esbuild` and `sharp` were approved with `npm install-scripts approve`. New packages that need install scripts need the same.
- Google Chrome is not installed. For screenshots, use Playwright (`npx playwright install chromium`).
- Don't cut scope from PLAN.md to save time; the user wants the full plan.
